title: Authentication
description: The two headers every request carries, and what each failure status means.
---

Partners authenticate every request with two credentials, sent as headers.

<ParamField header="client-id" param-type="string" required="true">
  Your Deepvue client identifier.
</ParamField>

<ParamField header="x-api-key" param-type="string" required="true">
  Your Deepvue API key.
</ParamField>

<Callout kind="alert">
  `x-api-key` is a secret.
  Keep it server-side.
  It must never be exposed in a browser or a mobile client.
</Callout>

Send both headers on every request.

```bash
curl 'https://api.deepvue.link/v1/workflows' \
  -H 'client-id: YOUR_CLIENT_ID' \
  -H 'x-api-key: YOUR_API_KEY'
```

## Authentication failures

| Status | Body | Meaning |
| --- | --- | --- |
| `401` | `{"error":"missing credentials: send client-id + x-api-key headers"}` | No usable credential was supplied. |
| `401` | `{"error":"invalid Deepvue credentials"}` | The credential pair was rejected. |
| `403` | `{"error":"account_disabled"}` | The account exists but is not yet approved. |
| `403` | `{"error":"Deepvue account not authorized for this surface"}` | The account is not authorized for this API. |
| `502` | `{"error":"deepvue authorize failed: …"}` | Authorization service temporarily unreachable. Retry. |
| `503` | `{"error":"auto-provisioning disabled - log in once via /auth/login first"}` | First-time setup not yet completed. |

## Bearer tokens

One route also accepts a dashboard Bearer token instead of the header pair: `POST /v1/signals/{run_id}/{signal_name}`, used to record a review verdict.
Every other route requires `client-id` and `x-api-key`.

<Callout kind="info">
  Retry `502` responses.
  Treat `401` and `403` as configuration problems rather than transient faults, and do not retry them in a loop.
</Callout>
