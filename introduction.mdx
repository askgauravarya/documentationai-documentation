title: Verification Workflows API

The Verification Workflows API is Deepvue's partner surface for running verification journeys end to end.
You define a workflow once in the dashboard, then use this API to start runs against it, follow each run to a terminal status, resolve anything that needs a human, and read the resulting report.

## The model

Four objects carry everything in this API.

<Columns cols={2}>
  <Card title="Workflow" icon="git-branch" horizontal="false">
    A verification journey you configured in the dashboard.
    Its `steps` tell you every check that can appear in a result.
  </Card>
  <Card title="Run" icon="play" horizontal="false">
    One execution of a workflow for one subject.
    It moves through a status lifecycle until it is terminal.
  </Card>
  <Card title="Check" icon="check-circle" horizontal="false">
    One logical verification step inside a run, with its own status and result data.
  </Card>
  <Card title="Decision" icon="gavel" horizontal="false">
    The human verdict on a run.
    An axis independent of status: `review`, `approve`, `reject`, or none owed.
  </Card>
</Columns>

The shape of a normal integration follows from that.

<Steps>
  <Step title="Start a run" icon="play">
    `POST /v1/workflows/{id}/runs` with your own `reference_id` for the subject.
  </Step>
  <Step title="Send the customer to the journey" icon="external-link">
    For interactive workflows the response already carries `action_required.url`.
  </Step>
  <Step title="Poll until terminal" icon="repeat">
    `GET /v1/runs/{id}` until `status` is `completed`, `failed`, `expired`, or `cancelled`.
  </Step>
  <Step title="Read the results" icon="file-text">
    Inspect `checks[]`, or fetch the report as JSON or PDF.
  </Step>
  <Step title="Resolve anything flagged" icon="user-check">
    Work the `?decision=review` queue and record a verdict.
  </Step>
</Steps>

## Two things that surprise most integrators

<Callout kind="info">
  `completed` means the workflow finished, not that every check passed.
  Inspect `checks[].status` to learn the verification outcome.
</Callout>

<Callout kind="info">
  A run can finish every screen and still be owed a human verdict.
  `status` says how far a run got; `decision` says where a human verdict on it stands.
  The two are independent and are AND-ed when you filter.
</Callout>
